# ADR-0024: A public demonstration instance on free hosting

- Status: Proposed
- Date: 2026-11-14

## Context

The demonstrator of ADR-0020 runs only on a developer's machine: point 3 of that ADR says "No deployment (ADR-0008 stays Proposed)". On 2026-11-11 the project owner deferred deployment and kept CAIPO local (Q-17). On 2026-11-14 the owner asked for the demonstrator to be reachable by a public link, so that people outside the project can open it. The owner set one condition: it must cost nothing.

ADR-0008 is the deployment of the research platform. That platform has isolated workers on separate networks with filtered egress (ADR-0009, ADR-0011). ADR-0008 rejects a platform-as-a-service for that reason, and the reason stands for Phase 2 and later. The demonstrator has none of those parts:
- no worker, no fetch, no parsing, no upload of files, no artifact store;
- no AI provider;
- no use of Redis at run time. Sign-in and registration throttling count in PostgreSQL.

What it needs is one web process and one PostgreSQL database. That is within what free hosting offers.

Three findings of the frozen diagnostic report were deferred to a deployment decision (I1, I2, I5). Email delivery in production also waits for ADR-0008 (ADR-0015, ADR-0016, ADR-0021).

## Decision (proposed)

1. **What is deployed.** One public instance of the demonstrator, built from `main`. It holds demonstration data and reference data only (ADR-0020 point 5). It never holds research records, personal data of anyone but the owner, or any document text.
   - It is not the deployment of the research platform. ADR-0008 stays Proposed for that.
   - This ADR amends ADR-0020 point 3 for this instance only.

2. **Hosting.** Both accounts are opened by the owner in the owner's name.
   - **Web:** a free web service on Render, in its Frankfurt region. The service builds the repository's container image and runs it as a non-root user. Render rebuilds it when `main` changes, which happens only when the owner merges a pull request. CI stays code checks only and deploys nothing (CLAUDE.md, rule 12).
   - **Database:** a free PostgreSQL project on Neon, in its Frankfurt region (AWS eu-central-1). The major version is the newest that Neon offers that the test suite passes on. Connections require TLS.

3. **Secrets.** The secret key, the TOTP encryption key, and the database password are generated by the owner and entered only in Render's settings. They are never in the repository, in a file the agent reads, or in a message to the agent.

4. **Schema and data are loaded from the owner's machine.** Render's free web services offer no shell (Render's page on free instances, read on 2026-11-14). So `migrate` and the seeding of the demonstration environment are explicit steps that the owner runs locally, with the database address in the environment of that one command. This keeps ADR-0008's rule that migrations are never run at container start.
   - Demonstration data are loaded by `seed_demo` with the development settings. That command keeps its rule that it runs only with DEBUG on, on the owner's machine.
   - Reference data are loaded by their existing commands.

5. **Who can do what on the instance.**
   - **Registration is closed:** no email can be sent, and the instance holds no visitor's personal data.
   - **The Reader account of the demonstration is shared.** Its address and password are shown on the sign-in page. It can read every page that a Reader can.
   - **The shared account cannot change itself:** its password, its email address, its second factor, or its sign-in history. It cannot submit an article. Each of these is refused by a service, not only hidden in the interface, and each refusal is tested.
   - **The Researcher account of the demonstration** keeps a password that the owner chooses and does not publish.
   - **No Administrator account is created on the instance.** It needs no administration: it is rebuilt from the repository and the seed.

6. **Hardening for this instance**, from diagnostic finding I1:
   - DEBUG off;
   - TLS redirect, trusting the proxy's `X-Forwarded-Proto` header from Render only;
   - HSTS;
   - secure session and CSRF cookies;
   - `CSRF_TRUSTED_ORIGINS` and `ALLOWED_HOSTS` set to the instance's own address;
   - `manage.py check --deploy` passing, or each remaining warning recorded with its reason.

   Static files are served by the web process with long cache lifetimes. A Content Security Policy and per-component database roles stay with ADR-0008. On this instance the application's database role owns its tables. That is accepted because the database holds only data that can be rebuilt.

7. **Client address (finding I2).** Behind Render's proxy, `REMOTE_ADDR` is the proxy for every visitor. Throttling uses the client address that Render's proxy records in `X-Forwarded-For`. Render is reported to append to a header the client sent rather than replace it, so the first entry can be forged. Throttling therefore takes the entry Render's own proxy adds, counted from the right, never one the client sent. This is set only in the instance's settings, and is tested with a forged header.

8. **What a visitor is told.**
   - A notice on every page says that the instance is a demonstration: its records are synthetic or reference data, and it is not the research platform.
   - It says that the server keeps standard request logs.
   - It says that the instance may sleep and take about a minute to wake.

## Alternatives considered

- **ADR-0008 as proposed: a rented server.** It would serve the research platform too, but it costs money each month, and the owner asked for no cost.
- **Oracle Cloud's free server.** It is a full virtual machine. But it needs a payment card to register, its free capacity was halved in 2026, and the free machines are often unavailable.
- **Render's own free PostgreSQL.** A free Render database expires 30 days after it is created (Render's page on free instances, read on 2026-11-14), so the instance would lose its data. Neon's free database has no expiry.
- **Opening the workspace pages to anonymous visitors.** No sign-in would be needed, but it reverses ADR-0007 and ADR-0020's access rules, and the public site is still waiting for P-2 and B7.
- **Screenshots only.** No hosting is needed, but a reader cannot try anything.

## Consequences

- The demonstrator can be opened by anyone with the link. The first request after about fifteen minutes without visitors takes about a minute.
- Free plans change and can end without notice. The instance holds nothing that cannot be rebuilt from the repository and the seed, so losing it loses no data.
- The application gains:
  - a container image definition;
  - an instance settings module;
  - a WSGI server and a static-file server, two new dependencies, each justified in its pull request;
  - the refusals of point 5.
- One person can lock the shared account for others for the length of the sign-in throttling window, by failing its sign-in on purpose. This is accepted for a demonstration.
- The break-glass command is not used on the instance, and no Administrator exists there, so I5 does not arise on it.

## Open points

Acceptance needs:

1. The current terms of Neon's free plan, and the region and container support of Render's, checked on their own pages when the accounts are opened. Render's page, read on 2026-11-14, confirms the sleep after 15 minutes, a wake of about a minute, no shell, and no payment card needed for a free service.
2. How Render's proxy sets `X-Forwarded-For` and `X-Forwarded-Proto`, which points 6 and 7 depend on. Only community reports were found on 2026-11-14. It is measured on the instance itself, with a forged header, before anyone is given the link.
3. The owner's acceptance of the wording that point 8 shows to visitors.

## Revisit when

- A free plan ends or changes its terms.
- The instance should hold anything beyond demonstration and reference data.
- The research platform is deployed under ADR-0008.
